# OpenBy UI 优化方案

2026-09-09 更新：采用统一纯色背景与直接可见的操作入口，取代此前的半透明侧栏、卡片底色；规则行的次要操作使用竖向三点菜单。

## 布局和外观

- 保留左右布局，左侧宽 224 pt；默认内容尺寸 1000 × 680 pt，最小窗口 800 × 560 pt。可拖动窗口边缘或角调整宽高；同次运行中重新打开窗口保留调整后的尺寸。
- 根视图绘制不透明的系统窗口背景，随浅色、深色外观更新。侧栏、滚动区域及分组透出同一背景；以标题、留白和细线区分内容。
- “添加文件类型…”位于左侧列表顶部。
- 当前类型标题下直接显示编辑、启用、停用并恢复原应用、移除四个独立按钮。不可执行的按钮置灰；部分启用时显示“启用剩余格式”。
- 规则行高 84 pt，文件夹信息、目标应用、“编辑…”和右侧竖向三点菜单同排并垂直居中；菜单提供“停用／启用”和“删除…”。移除上移、下移按钮，保留拖动排序及删除确认。
- 规则列表最多显示五行，更多规则可滚动；详情整体也支持纵向滚动。窗口缩小时保持相同操作布局。
- 使用原生控件与系统字体，选中状态和操作按钮保留必要的对比度。

## 左栏条目状态（2026-09-09）

- 选中项使用 8 pt 圆角淡强调色背景及 3 × 18 pt 左侧短竖条，标题略加粗，图标保留原色。维持 56 pt 行高及 4 pt 行间距。
- 第二行保留灰色后缀数量，状态使用圆点及文字：已启用为绿色、尚未启用为红色、部分启用为橙色。浅色模式使用较深的状态色，深色模式使用系统状态色。
- 未选中项悬停时显示淡灰背景。选中状态在右侧操作时保留，窗口失去焦点时减弱；键盘焦点使用细边框。背景过渡为 120 ms，尊重系统减少动态效果设置；增强对比度时增加选中边框。
- 编译及 13 项窗口尺寸回归检查通过，并用临时配置导出浅色、深色三种启用状态的预览核对样式；未改变真实系统文件关联。

## 文案

- 主入口统一称“文件类型”；编辑表单说明多个后缀可共用规则。
- “位置规则”改为“文件夹规则”，“其他位置”改为“未匹配规则时”，“更改…”改为“更换应用…”。
- 规则状态统一使用“启用／停用”。
- 空态为“按文件夹设置打开应用”，简要说明添加类型、设置规则、启用自动打开的顺序。
- 保存配置的提示不宣称自动打开已经生效；规则预览说明需要启用自动打开及该规则。
- 保留错误原因、删除确认和恢复原应用的说明。预设下拉框仍用于选择输入值，不承载功能操作。

## 实现边界

主入口为 `Sources/OpenBy/UI/SettingsWindowController.swift`。没有修改配置格式、规则匹配算法或公共 API。

启用和停用使用明确的独立动作，不再依据菜单项类型判断。规则按钮通过规则 UUID 找到当前行，避免重排后操作错位。关联更新期间禁用冲突操作及拖动排序。

## 验证

- Swift 构建通过；现有测试运行器 79 项用例全部通过。
- 使用临时配置和模拟关联服务检查部分启用后停用、恢复失败后的可重试状态、规则重排后按 UUID 操作、首行上移禁用和规则启停。
- 原生窗口检查覆盖默认和最小尺寸、浅色与深色、长中文路径及应用名、多规则、零规则、空配置。
- UI 验证不写入真实系统默认应用关联。VoiceOver 实际朗读和跨 macOS 版本实机验证不在本轮结果内。

### 规则行操作精简

按用户要求，规则行只常显编辑与竖向三点入口，位于目标应用右侧，与条目主体同排；菜单操作携带规则 UUID，停用后可在同一菜单重新启用。排序说明同步改为拖动排序，关联更新期间禁用编辑和菜单入口。类型级按钮维持原布局。

### 窗口宽度回归修复

类型操作行补充可伸缩留白，避免四个按钮的 required hugging 将窗口宽度锁定在约 668 pt。根视图增加最小宽高约束，因为 AppKit 在 Auto Layout 下不采用 `window.minSize` 作为最终尺寸限制。默认内容宽度 1000 pt，布局完成后仍可自由缩放。

运行 `scripts/check-window-layout.sh` 可验证实际窗口宽度：默认 1000、800/1000/1440 间调整、未启用/部分启用/全部启用、关闭后重开、最小尺寸及空配置。测试使用临时配置且禁止写入系统关联；本轮 13 项尺寸检查全部通过。
