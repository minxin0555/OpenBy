# OpenBy UI 美化方案

状态：已完成 AppKit 实施（2026-09-07）。以下保留设计依据；交互草案使用示例数据。实际界面已通过独立预览应用检查，验证过程中未修改用户的系统默认关联。

## 1. 设计方向

采用安静、清晰的 macOS 原生工具风格：柔和侧栏、清楚的字体层级、结构化规则行、少量蓝色主操作。保留现有「文件类型 → 位置规则 → 其他位置 → 预览结果」任务顺序。

当前主入口为 `Sources/OpenBy/UI/SettingsWindowController.swift`。本次设计围绕这一主从界面展开。

## 2. 当前问题与对应改动

| 从代码观察到的问题 | 设计改动 |
| --- | --- |
| 侧栏仅用同一文本控件显示扩展名和状态 | 类型图标、名称、规则数量分层；状态同时有文字提示 |
| 启用、移除、帮助和规则操作均以文字按钮分散排列 | 启用操作放顶部；添加放规则标题旁；编辑放行内；移除收进更多菜单；帮助放侧栏底部 |
| 规则把位置、范围和应用拼成一句话 | 拆成「文件夹与路径」「范围」「目标应用」三个视觉层次 |
| 表格使用交替底色、系统边框，上下再加分隔线 | 改成一个浅边框分组列表，行间细线分隔 |
| 结果和长操作按钮挤在底部同一行，结果最多两行 | 预览独立区域，结果在下方展开并允许换行 |
| 编辑规则使用 NSAlert 的 accessoryView 拼装表单 | 改为附着主窗口的专用 sheet，统一对齐和底部操作区 |

## 3. 主窗口

- 默认尺寸建议 960 × 680 pt；最小尺寸保留 800 × 560 pt。
- 侧栏宽 216–232 pt，默认 224 pt；主内容边距 28 pt，区块间距 24 pt。
- 主内容过高时整体滚动；窗口变矮时优先保证控件可达，不挤压文字。
- 标题栏使用系统窗口控件和简洁的 OpenBy 标题，与侧栏材质协调。

### 文件类型侧栏

每行约 56 pt：左侧 28 pt 类型图标，右侧第一行「PDF 文档」，第二行「2 条规则 · 已启用」。扩展名不唯一时可显示「YAML 文件」和 `.yaml / .yml`，类型仍按现有模型归并。

选中行使用系统选中样式和圆角。底部保留「添加文件类型…」「帮助与诊断」；首版不增加搜索、收藏和分类管理。

### 详情顶部

左侧文件类型图标、名称、扩展名。右侧放自动打开状态与操作、更多菜单。

- 未启用：中性状态文字 + 蓝色「启用自动打开」。
- 已启用：绿色图标 +「已启用」文字；停用及移除放入更多菜单。
- 正在应用：显示「正在启用… / 正在恢复…」，防止重复触发。
- 失败或默认关联变化：显示具体原因与「重试 / 重新启用」；状态以系统验证结果为准。

这里保留显式按钮，不采用点击后立即变色的乐观开关，因为系统关联变更可能失败或被取消。停用操作继续清楚说明将恢复原应用。

### 位置规则

标题「位置规则」，说明「从上到下匹配，首条符合的规则生效」，右侧唯一高强调操作「添加规则」。未启用类型的主按钮优先用于启用，添加使用次级样式。

规则行建议 68–76 pt，结构如下：

`拖动柄 / 顺序号  文件夹图标 + 文件夹名      →  应用图标 + 应用名  编辑`

第二行显示缩写路径与「包含子文件夹 / 仅当前文件夹」。路径中间截断，保留路径开头和末级目录；可通过提示或编辑页读取完整路径。

- 拖动时显示明确插入线；在行菜单补充「上移 / 下移」作为键盘替代。
- 编辑为可见操作；关闭规则和移除收进编辑页或行菜单。
- 停用规则降低强调但保持可读，并显示「已关闭」。
- 缺失应用、不可用文件夹在对应行显示图标和原因，不仅在页头笼统报错。
- 无规则时列表区域显示简短解释「所有文件将使用下方应用打开」，沿用标题旁的添加入口。

### 其他位置

用独立的紧凑分组承载：「没有规则匹配时」+ 应用图标与名称 +「更改…」。视觉权重低于规则列表，语义保持清晰。

### 预览打开结果

独立轻量区域，入口「选择文件…」，说明「仅预览，不会打开文件」。

结果示例：`示例.pdf → PDF Expert`，下一行解释「命中第 1 条规则 · Papers（包含子文件夹）」。未匹配时显示「使用其他位置的应用」。未启用时标注「配置预览，自动打开尚未启用」。

首版继续用系统文件面板预览；窗口拖入文件仍执行现有的添加类型操作，避免同一拖放位置产生歧义。

## 4. 编辑、空态与诊断

规则编辑 sheet 建议宽 520 pt。自上而下为文件夹选择、包含子文件夹选项、目标应用选择、启用状态和一句话结果预览；底部固定「取消 / 保存规则」。未选完整时禁止保存并就地说明缺少什么。保留完整路径可访问性和系统选择面板。

首次使用空态：一个适度大小的分流图标，标题「让文件找到合适的应用」，一句解释和「选择示例文件…」。三步引导改成较轻的横向说明；文件拖入时突出接收区域。

帮助与诊断：继续独立窗口，分为「应用信息」「状态检查」「打开性能」「最近问题」。技术标识和配置路径留在这里。检查使用列表表达；详细错误允许展开、选择与复制。

## 5. 视觉规范

| 项目 | 建议 |
| --- | --- |
| 字体 | 系统字体；标题 24 pt / semibold，区块标题 14 pt / semibold，正文 13 pt，辅助文字 11–12 pt |
| 间距 | 使用 4 / 8 / 12 / 16 / 24 / 28 pt，按层级复用 |
| 圆角 | 分组 10 pt，图标底板 8 pt；系统按钮保留原生形态 |
| 背景 | 主区域系统窗口底色，列表使用系统内容底色，侧栏使用 sidebar material |
| 颜色 | 系统强调色用于主要操作；绿为已启用，橙为需注意，红为失败；状态必须配文字 |
| 图标 | SF Symbols 表达文件夹、排序和状态；文件及应用优先使用系统提供的真实图标 |
| 边界与阴影 | 1 px 语义边框；窗口内不叠加大阴影 |
| 动效 | 仅局部展开和重排，约 120–180 ms；遵守减少动态效果设置 |
| 外观 | 跟随浅色、深色外观；适配提高对比度和减少透明度 |

## 6. 实现顺序与验收

1. 主窗口视觉基础：尺寸、排版、侧栏、标题和按钮层级。
2. 规则自定义行、其他位置分组、可展开预览结果。
3. 专用规则编辑 sheet、空态、异常状态、诊断布局统一。

继续使用 AppKit，可从主控制器提取可复用的类型行、规则行、分组容器和编辑控制器。图标只在设置界面按需加载并缓存；界面调整不得给文件转发路径新增同步工作。

验收覆盖：浅色和深色；800 × 560 与默认窗口；空配置、零规则、多规则；长中文路径和应用名；未启用、启用中、失败、已停用规则、缺失目标；键盘操作、VoiceOver 标签、拖动排序及替代操作；预览不实际打开文件；停用和移除保持现有恢复逻辑。实施后运行现有测试运行器并进行原生窗口实测。

交互草案 `openby-ui-concept.html` 用来评审层级、间距和操作位置；示例应用以通用图标代替真实图标，浏览器绘制的控件不代表最终 AppKit 像素效果。
